# NTトレーニングメニュー 運用マニュアル

ナショナルチームの選手が、スマートフォンからその日のトレーニングメニューと参考動画を
確認するためのWebアプリです。このファイルは**運用担当者（Van）向け**の手順書です。

---

## ⚠️ 最初に読んでください（公開範囲の話）

このアプリは **GitHub Pages** で公開します。GitHub の無料プランでは
**非公開（private）リポジトリからページを公開できない**ため、
**リポジトリは public（誰でも見られる状態）で作成します。**

つまり：

- **リポジトリの中身は誰でも見られます。** メニューの種目名も、動画IDも、このREADMEもです。
- **YouTubeの「限定公開」は鍵ではありません。** URL（＝動画ID）を知っている人は誰でも見られます。
  そして動画IDはこのリポジトリの `data/training-data.json` に書いてあります。

そのため、次の運用ルールを必ず守ってください。

| 守ること | 理由 |
|---|---|
| 動画のタイトル・説明欄・メニューデータに**選手の氏名や個人情報を入れない** | 誰でも見られるため |
| 動画に**ホワイトボード・連絡先・他選手の評価**などを映さない | 同上 |
| アプリURL・限定公開URLを**SNSや公開ページに貼らない** | 拡散を防ぐため |
| **秘密性の高い映像**（戦術・医療情報・個人評価が映るもの）はこの仕組みに載せない | 保護できないため |
| 動画は必ず **`japanmogulteam@gmail.com`（チーム共用アカウント）** にアップする | 担当者が代わってもチャンネルを引き継げるようにするため。個人アカウントに分散させない |

## 1. GitHub Pages への公開手順（最初の1回だけ）

### 1-1. リポジトリを作る

1. <https://github.com/> にログインする（チームで管理しているアカウント推奨）。
2. 右上の「＋」→「New repository」。
3. 次のように設定する。
   - **Repository name**：`nt-training`（お好きな名前で構いません。URLに出ます）
   - **Public** を選ぶ ← **Private にすると Pages で公開できません**
   - 「Add a README file」は**チェックしない**（このフォルダのREADMEを使うため）
4. 「Create repository」を押す。

### 1-2. ファイルを置く

作成直後の画面にある「**uploading an existing file**」（または Add file → Upload files）を押し、
このフォルダの中身を**フォルダ構造そのまま**アップロードします。

```
（リポジトリの直下）
├─ index.html
├─ styles.css
├─ app.js
├─ manifest.webmanifest
├─ sw.js
├─ offline.html
├─ README.md
├─ data/
│   └─ training-data.json
├─ icons/
│   ├─ icon.svg
│   ├─ icon-192.png
│   ├─ icon-512.png
│   ├─ icon-maskable-512.png
│   └─ apple-touch-icon.png
└─ admin/
    └─ timestamp.html
```

> **注意**：`index.html` は必ず**リポジトリの一番上**に置いてください。
> `NTトレーニングメニューアプリ` のような入れ物フォルダごとアップロードすると、
> URLが1段深くなって分かりにくくなります。

アップロードできたら、下の「Commit changes」を押します。

### 1-3. Pages を有効にする

1. リポジトリの上部メニュー「**Settings**」を開く。
2. 左メニューの「**Pages**」。
3. 「Build and deployment」の **Source** を `Deploy from a branch` にする。
4. **Branch** を `main`、フォルダを `/ (root)` にして「Save」。
5. 1〜2分待つと、同じ画面の上に公開URLが表示されます。

### 1-4. URLを確認する

公開URLはこの形になります。

```
https://<GitHubのユーザー名>.github.io/<リポジトリ名>/
```

例：ユーザー名が `japanmogulteam`、リポジトリ名が `nt-training` なら
`https://japanmogulteam.github.io/nt-training/`

**最後のスラッシュ `/` まで含めて**選手に伝えてください。

## 2. ローカル（自分のパソコン）で動作確認する方法

**`index.html` をダブルクリックで開いても、メニューは表示されません。**

理由：ブラウザは `file://` で開いたページからのファイル読み込み（`fetch`）を
セキュリティ上ブロックするため、`data/training-data.json` を読めません。
画面には「メニューデータを取得できませんでした」と出ます。**アプリの不具合ではありません。**

確認したいときは、簡易サーバーを立てて `http://` で開きます。次のどれかでOKです。

**A. Python が入っている場合**

このフォルダで「コマンドプロンプト」または「ターミナル」を開いて：

```bash
python -m http.server 8000
```

そのままブラウザで `http://localhost:8000/` を開く。止めるときは `Ctrl + C`。

**B. Node.js が入っている場合**

```bash
npx serve .
```

**C. VS Code を使っている場合**

拡張機能「Live Server」を入れて、`index.html` を右クリック →「Open with Live Server」。

> `admin/timestamp.html`（開始秒つくるくん）は**ダブルクリックで開いてOK**です。
> こちらは外部ファイルを読まないので `file://` でも動きます。

## 3. 新しい練習日を追加する手順 ★ここが一番よく使います★

### 手順の全体像

> ① YouTubeに動画をあげる → ② 動画IDを控える → ③ 開始秒を作る
> → ④ `training-data.json` に追記する → ⑤ `updatedAt` を直す
> → ⑥ GitHubにコミット → ⑦ スマホで確認

---

### ① YouTubeに「限定公開」でアップロードする

1. **必ず `japanmogulteam@gmail.com` でYouTubeにログイン**する。
   （個人アカウントに上げないでください。動画はすべてこのチャンネルに集約します）
2. 右上のカメラアイコン →「動画をアップロード」。
3. 動画ファイルを選ぶ。
4. **タイトル**：`2026.8.3 アジプラTR` のように「日付＋種別」だけにする。
   **選手名は入れない。**
5. 説明欄も空、または種目名程度にとどめる。**個人情報を書かない。**
6. 「視聴者」の設定で「**いいえ、子ども向けではありません**」を選ぶ。
7. 公開設定の画面で「**限定公開（Unlisted）**」を選ぶ。
   - 「非公開（Private）」にすると**アプリで再生できません**。必ず「限定公開」です。
8. 「保存」。

### ② 動画IDを取り出す

アップロード後の動画URLは、次のどちらかの形です。

```
https://youtu.be/dQw4w9WgXcQ
https://www.youtube.com/watch?v=dQw4w9WgXcQ
```

この `dQw4w9WgXcQ` の部分（11文字）が**動画ID**です。これをメモします。
`?` より後ろの `&t=30s` などは含めません。

### ③ `admin/timestamp.html` で開始秒リストを作る

**YouTubeにアップする前のローカルmp4で作業できます。**（先にやってもOK）

1. `admin/timestamp.html` をダブルクリックで開く。
2. 「1. 動画を選ぶ」でその日のmp4を選ぶ。
3. 「2. その日の種目名を貼り付ける」に、**メニュー表と同じ順番で**種目名を改行区切りで貼り、
   「読み込み」を押す。
4. 動画を再生し（`K`キーで再生／停止）、**各種目の実演が始まった瞬間に `Space` キー**を押す。
   押すたびに記録され、対象が自動的に次の種目へ進みます。
   - 行き過ぎたら `←` `→` で1秒ずつ、`Shift + ←` `→` で0.1秒ずつ動かせます。
   - 押し間違えたら `Backspace` で直前の記録を取り消せます。
   - 各行の「修正」から手入力で直すこともできます。「再生」でその場で確認できます。
5. 全部記録できたら、「**0.5秒 手前に補正して出力する**」に**チェックを入れる**ことをおすすめします。
   構えの姿勢から見られて、シークのズレも吸収できます。
6. 「**JSONをコピー**」を押す。次のような内容がコピーされます。

```json
[
  { "no": 1, "name": "ステップ→キャッチドリル（PP/ハーキー/クイックツイスト/タックJ）", "start": 4.2 },
  { "no": 2, "name": "紐飛び3種距離", "start": 11.9 }
]
```

> **補正について**：0.5秒の補正は「書き出すとき」に1回だけかかります。
> 記録した時刻そのものは変わらないので、チェックを何度ON/OFFしても
> **数字がどんどんズレていくことはありません**。安心して切り替えてください。

> **途中でやめるとき**：右側の「② 作業の保存用」をコピーしてメモ帳などに貼っておけば、
> 「5. 前に作ったものを読み戻して直す」から続きができます。

### ④ `data/training-data.json` に1ブロック追記する

`data/training-data.json` を開き、`"sessions": [` のすぐ後ろ（＝**リストの先頭**）に
新しいブロックを貼り付けます。**先頭に入れると、アプリでも一番上（最新）に出ます。**

**コピペ用の空テンプレート：**

```json
    {
      "id": "2026-08-10-core",
      "date": "2026-08-10",
      "title": "2026.8.10 コアTR",
      "category": "コア",
      "youtubeId": "ここに動画IDを貼る",
      "duration": 85,
      "exercises": [
        {
          "id": "2026-08-10-core-01",
          "no": 1,
          "group": "カテゴリ名",
          "name": "種目名",
          "detail": "",
          "prescription": "10回×1",
          "aliases": [],
          "start": null,
          "end": null,
          "notes": ""
        },
        {
          "id": "2026-08-10-core-02",
          "no": 2,
          "group": "カテゴリ名",
          "name": "種目名",
          "detail": "",
          "prescription": "10回×1",
          "aliases": [],
          "start": null,
          "end": null,
          "notes": ""
        }
      ]
    },
```

**各項目の意味：**

| 項目 | 何を書くか |
|---|---|
| `id` | 他と重ならない名前。`日付-種別` の形にそろえる（例 `2026-08-10-core`） |
| `date` | `YYYY-MM-DD`。**この形式でないとその日は表示されません** |
| `title` | 画面に出るタイトル（例 `2026.8.10 コアTR`） |
| `category` | `"アジプラ"` か `"コア"` のどちらか |
| `youtubeId` | ②で控えた11文字。**まだ無いときは `""`（空）のままでOK** |
| `duration` | 動画のおおよその秒数。分からなければ `85` のままで構いません |
| `group` | メニュー表の「カテゴリ」列（例 `中臀筋`）。同じ値が続くと見出しにまとまります |
| `name` | 種目名。**メニュー表の原文どおり**に書く |
| `detail` | 種目名のうしろのカッコの中身。画面では `name（detail）` と表示されます。無ければ `""` |
| `prescription` | 「回数・セット数」列。**原文どおり**に書く |
| `start` | ③で作った開始秒。**まだ無いときは `null`** |
| `end` / `notes` / `aliases` | 今は使いません。`null` / `""` / `[]` のままで結構です |

**書くときの注意：**

- 種目は**メニュー表と同じ順番**に並べてください。動画の順番とそろえるためです。
- `id` は種目ごとにも重ならないようにします（`セッションid-01`, `-02`… とするのが安全）。
- **最後のブロックの後ろにカンマを付けない。** これが一番多いミスです。
- `youtubeId` が空でも、`start` が全部 `null` でも、アプリは普通に動きます。
  メニュー表だけ先に出して、動画は後から足す運用で構いません。

### ⑤ `updatedAt` を更新する

ファイルの上のほうにある `updatedAt` を、今の日時に書き換えます。
これが画面の「データ更新：〜」に出ます。

```json
  "updatedAt": "2026-08-10T21:30:00+09:00",
```

形式は `年-月-日T時:分:秒+09:00` です。`+09:00` は日本時間の意味なので、そのまま残します。

### ⑥ GitHubにコミットする

1. GitHubのリポジトリで `data` フォルダ →`training-data.json` を開く。
2. 右上の**鉛筆アイコン**（Edit this file）を押す。
3. 内容を書き換える。
4. 下の「Commit changes」を押す。

> **貼り付ける前に、書式チェックをおすすめします。**
> <https://jsonlint.com/> に全文を貼って「Validate JSON」を押すと、
> カンマ抜けなどをその場で教えてくれます（日本語は文字化けして見えますが判定は正しいです）。

### ⑦ スマホで開いて確認する

1〜2分待ってから、公開URLをスマホで開きます。
すでに開いたことがある端末では、画面の上に

> **新しいバージョンがあります　［更新する］**

と出ることがあります。［更新する］を押すと最新になります。

## 4. よくある失敗と対処

### (A) 画面に「メニューデータの書式が壊れているため読み込めませんでした」と出る

`data/training-data.json` の書式ミスです。**アプリが壊れたわけではありません。**
この状態でも、その端末で前に読み込めたメニューが表示され続けます。

**直し方：**

1. パソコンのブラウザでアプリを開く。
2. `F12` キー → 「Console（コンソール）」タブを開く。
3. 赤い文字で次のようなメッセージが出ています。

   ```
   SyntaxError: Expected ',' or '}' after property value in JSON at position 32 (line 3 column 5)
   ```

   → **line 3（3行目）あたり**が原因、という意味です。
4. `training-data.json` のその行の**前後**を見て、次を確認します。
   - 行の終わりの **カンマ `,`** が抜けていないか
   - **かっこ `}` `]`** の数が合っているか
   - 文字列を囲む **ダブルクォート `"`** が閉じているか
   - **最後の要素のうしろにカンマが余っていないか**
5. 分からなければ <https://jsonlint.com/> に貼って確認するのが確実です。

### (B) スマホに古い内容が残っている

このアプリはオフラインでも使えるように、端末に保存する作りです。そのため
更新直後は古い内容が出ることがあります。次の順で試してください。

1. アプリを開いたまま**数秒待つ**。「新しいバージョンがあります」が出たら［更新する］を押す。
2. 出ない場合は、いったんアプリを閉じて開き直す。
3. それでも古いときは、Safari で **ページを下に引っぱって再読み込み**する。
4. 最終手段：iPhone の「設定」→「Safari」→「履歴とWebサイトデータを消去」。
   （ホーム画面に追加したアイコンから開いている場合は、いったん削除して追加し直す）

> なお、**メニューデータは常に通信を優先して取りに行く**設計です。
> 電波がある状態で開けば、たいてい1回目で最新になります。

### (C) 動画が再生できない

上から順に確認してください。

1. **YouTube側の公開設定**が「限定公開」になっているか。
   →「非公開（Private）」だと、アップした本人以外は再生できません。
2. **動画IDが合っているか**。`data/training-data.json` の `youtubeId` を確認。
   11文字ちょうどで、`https://` や `?t=30` が混ざっていないか。
3. **通信があるか**。画面右上が「オフライン」になっていませんか。
   動画の再生には通信が必要です。
4. 動画を**削除・再アップロード**すると動画IDが変わります。上げ直したときは必ずIDも直してください。

### (D) 「指定された練習日が見つかりませんでした」と出る

古いリンクを開いたときに出ます。一覧から選び直せば問題ありません。

## 5. 選手への案内文テンプレート

そのままコピーして送れます。URLの部分だけ差し替えてください。

```
【トレーニングメニューのページ】

その日のメニューと、種目の実演動画をまとめました。
https://＜ユーザー名＞.github.io/＜リポジトリ名＞/

・ブラウザで開いて「ホーム画面に追加」しておくと、次から速く開けます。
　（iPhone：共有ボタン → ホーム画面に追加 ／ Android：メニュー → ホーム画面に追加）
・メニュー表と検索は、電波がなくても使えます。
・動画の再生には通信が必要です。ジムに入る前に開いておくと安心です。
・動画には種目名と回数のテロップが入っているので、音を出さなくても分かります。
・種目の右の「実演を見る」を押すと、その種目のところから動画が始まります。

※このURLはSNSなどに貼らないでください。
```

## 6. オフラインで使える範囲・使えない範囲

**大前提：一度もオンラインで開いたことがない端末では、オフラインでは使えません。**
初回だけは必ず通信できる場所で開いてください（そのときに端末へ保存されます）。

| 機能 | オフラインで |
|---|---|
| 練習日の一覧 | ✅ 使える |
| 種目名・回数・セット数の閲覧 | ✅ 使える |
| 種目名の検索 | ✅ 使える |
| カテゴリ（アジプラ／コア）の絞り込み | ✅ 使える |
| 日付ごとの詳細表示 | ✅ 使える |
| **YouTube動画の再生** | ❌ **使えない** |
| **種目の頭出し再生** | ❌ 使えない（オンラインに戻れば使えます） |
| 新しく追加したメニューの取得 | ❌ 使えない（次にオンラインで開いたときに更新されます） |

動画が使えないのは技術的な制限です。YouTubeの動画は別のサイトにあるため、
このアプリ側で端末に保存しておくことができません。

オフラインのときに動画ボタンを押すと、次のように表示されます。

> 動画の再生にはインターネット接続が必要です。メニュー表はオフラインでも確認できます。

## 7. ファイル構成（参考）

| ファイル | 中身 | 触る頻度 |
|---|---|---|
| `data/training-data.json` | **メニューのデータ** | ★毎回 |
| `admin/timestamp.html` | 開始秒を作る管理者用ツール（選手には配りません） | ★毎回 |
| `index.html` | 画面の骨組み | ほぼ触らない |
| `styles.css` | 見た目 | ほぼ触らない |
| `app.js` | 動作 | ほぼ触らない |
| `sw.js` | オフライン保存の仕組み | ほぼ触らない |
| `offline.html` | 未保存の端末がオフラインで開いたときの画面 | ほぼ触らない |
| `manifest.webmanifest` | ホーム画面に追加したときの名前とアイコン | ほぼ触らない |
| `icons/` | アイコン画像 | ほぼ触らない |

`app.js` や `sw.js` を修正した場合は、`sw.js` の先頭にある

```js
var CACHE_VERSION = 'nt-training-v1';
```

の `v1` を `v2`、`v3`… と上げてからコミットしてください。
これで各端末に「新しいバージョンがあります」の案内が出ます。
（`data/training-data.json` を変えるだけなら、上げる必要はありません）

## 8. 今は入れていない機能

要望が出たときのために、意図的に入れていないものを記録しておきます。

- ログイン・選手ごとの個別URL（運用を単純に保つため）
- 実施チェック・トレーニング記録の保存
  （端末ごとの保存になり、機種変更で消える／チームの実施管理と食い違うため）
- お気に入り／最近見たメニュー／区間リピート／画面の常時点灯
- 動画のアプリ内保存・オフライン再生

データの形（`end` を空けてあるなど）は、あとから「区間リピート」や「お気に入り」を
足せるようにしてあります。
